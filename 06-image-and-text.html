  • No gutters. Tiles butt against each other so the block reads as one band. That is what makes the module feel deliberate at any item count, rather than like cards that happen to be sitting near each other.
  • Title and body both clamp to two lines each, so the row stays level whatever length of copy an editor writes.
  • Shown in greys. In the live design these use the Frontier palette — see the tone sequence below.

Notes from the session with developers

  • This is a new BO item — it is not built from an existing content type.
  • Background colour is set from a theme picker drawing on the brand palette; no selection made defaults to a fallback colour (still to be confirmed).
  • The chosen theme dictates the text colour, so contrast stays accessible without the editor having to set it separately.
  • The icon is selected by the editor in the CMS — it is not inferred automatically from the content.

  • 1Position drives tone, not the editor. The sequence runs mid → dark → pale and repeats, so any count produces a balanced arrangement. Four items form a 2 × 2 rather than a cramped single row.
  • 2Icons are on by default but can be switched off per module. Useful for a band where the titles are self-explanatory, and it means the module is usable straight away on pages where no icon has been drawn yet.
  • One decision left before visual design: the icon set. These need to be a single family — same weight, same grid, drawn to order — or the tiles will look assembled from different places. Roughly a dozen would cover the linking pages across the site. Worth confirming whether Frontier has an existing set we should extend.
  • Tone assignment should also be checked for contrast: the dark tile needs white text at a ratio that passes AA, which constrains which brand colours can take that position.
